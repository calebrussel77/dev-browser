# PR 4 — concurrence par page et sandboxes chaudes

Mesures du 17 septembre 2026 sur Windows 11, Chromium headless Playwright 1.61.1 et le Chrome connecté sur CDP 9223.

## Verrouillage

Le verrou du daemon est maintenant hiérarchique :

- une connexion, reconnexion, fermeture de browser ou exécution de script prend le verrou exclusif du browser ;
- une commande interactive ou vidéo prend seulement le verrou de sa page après la préparation du browser ;
- deux pages distinctes peuvent progresser en parallèle, tandis que deux actions sur la même page restent sérialisées ;
- une reconnexion attend les pages actives et empêche de nouvelles actions de démarrer.

Le test unitaire exécute deux actions de 300 ms sur deux pages en moins de 500 ms. Les mêmes actions sur une page prennent au moins 550 ms. Sur deux onglets LinkedIn, deux `observe` lancés simultanément prennent 1 329 ms, contre 1 055 ms pour la commande individuelle la plus lente : 1,26×, sous le plafond de 1,3×.

## Pool QuickJS

Une sandbox initialisée est conservée par browser et par configuration de limites. La sandbox consommée n'est jamais réutilisée : sa destruction est lancée après le nettoyage de l'exécution, pendant qu'une nouvelle sandbox est préparée en arrière-plan. Le pool est invalidé quand l'objet browser se déconnecte ou change.

| Script trivial | Avant PR 4 | Après PR 4 |
|---|---:|---:|
| premier passage | 155 à 265 ms | 417 ms |
| second passage chaud | 155 à 265 ms | 13 ms |

Le premier passage prépare simultanément l'instance courante et la prochaine instance isolée ; ce coût froid est assumé pour garantir un deuxième démarrage rapide. Le test de sécurité vérifie qu'une variable globale du premier script est absente du second et que la reconnexion n'utilise pas une sandbox liée à l'ancien browser.

## Benchmark de fiabilité

Les garde-fous maintenus sont resserrés et passent :

- maximum du couple `find + click` inférieur à 2 000 ms ;
- médiane du couple inférieure à 600 ms ;
- réponse `observe` compacte inférieure à 12 000 octets ;
- action sur la page de 2 000 éléments inférieure à 1 000 ms.

La passe de benchmark générale mesure aussi 4 209 octets compacts pour la fixture `observe`, 203 ms pour le clic lourd et 198 ms pour le type lourd.
