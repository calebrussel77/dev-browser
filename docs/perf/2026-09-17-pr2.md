# PR 2 — latence des actions et attentes ciblées

Mesures du 17 septembre 2026 sur Windows 11, Chromium headless Playwright 1.61.1 et le Chrome connecté sur CDP 9223. Les valeurs « avant » viennent de `docs/perf/baseline.md`. La passe locale ci-dessous est la passe non instrumentée stable ; une passe CDP séparée sert uniquement au comptage des messages.

Le plafond de 60 messages du clic lourd n'est pas encore atteignable dans cette PR : `raw: resolveActionTarget` consomme à lui seul 159 messages CDP, contre 177 pour l'action complète. La tâche 2.3 fusionne précisément cette résolution et reste le bloqueur mesuré.

## Attentes et perceptions

- `collectPageState({ reuseIfEpoch })` rend un nouveau `stateId` sans nouveau parcours quand le document, l'epoch et le scope sont inchangés.
- Les tests instrumentés comptent au plus une collecte complète pour `click`, `click --shot` et `type`.
- Une attente texte, dialog et ref sur 5 000 éléments termine en moins de 300 ms dans le test de régression.
- Les refs suivis au-delà de l'ancien plafond de 1 000 éléments sont lus directement via `byRef`.
- Une correspondance texte prouvée réussit même si une autre couverture est tronquée ; une absence sur texte réellement tronqué reste « non prouvée ».
