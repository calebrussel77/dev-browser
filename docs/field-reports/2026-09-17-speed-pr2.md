# Field report — PR 2 vitesse agent

Exécution contrôlée le 17 septembre 2026 sur le Chrome du propriétaire exposé en CDP 9223. Les noms de contacts, messages, refs applicatives et contenus de conversation ne sont pas consignés.

## Scénarios

| Scénario | Résultat | Mesure / observation |
|---|---|---|
| S3 — ouvrir un fil | fonctionnel, seuil ouvert | Une ligne non active a été ciblée comme `div[tabindex=0]`. Cinq clics sur ref ont réussi : 3 738, 3 343, 2 900, 2 324 et 2 808 ms, médiane 2 900 ms. Le fil attendu était actif après le clic. |
| S3 — click + wait-text | fonctionnel, seuil ouvert | La condition texte a réussi sans timeout ; `waitResult.elapsedMs` vaut 1 874 ms. Le seuil de 1,5 s reste dépassé. |
| S4 — menu d'options | anomalie de sémantique | Le clic ouvre bien le dropdown (`aria-expanded=true`, surface visible), mais LinkedIn ne lui donne ni rôle `dialog` ni rôle `menu`. `--wait-dialog opened` expire donc après 5 s. Un find frais puis `press Escape` ferme le dropdown (`aria-expanded=false`, surface invisible). |
| S10 — bouton d'envoi vide | succès | Un unique bouton d'envoi réellement désactivé a été trouvé avec l'état `disabled`. Le clic a été refusé, exit 3, diagnostic `TARGET_DISABLED`. Aucun envoi. |
| S10 — token de confirmation | non exécuté live | Aucun bouton Connect visible n'était disponible sur le feed restauré. Les tests automatisés de confirmation restent verts ; aucun token live n'a été émis ni consommé. |

## Analyse

Le clic live reste plus lent que la cible de PR 2, malgré la suppression du settle fixe et des perceptions redondantes. Le compteur local explique le résidu : `resolveActionTarget` représente 159 messages CDP, contre 177 pour le clic lourd complet. La tâche 2.3 est donc le bloqueur concret, et non le nouveau wait-engine.

Le cas S4 ne révèle pas une troncature : le dropdown est détectable et visible, mais sa sémantique DOM ne correspond pas à `dialog`. Une future attente `menu`/`popover`, ou une condition fondée sur `aria-expanded`, est nécessaire pour ce composant LinkedIn.

## Hygiène et état final

- Aucun message saisi, envoyé ou publié ; aucun like, connexion, follow, suppression, upload, paiement ou réglage.
- Le bouton d'envoi désactivé n'a produit aucun effet de bord.
- Le dropdown d'options a été fermé avec Escape.
- L'onglet LinkedIn a été restauré sur `/feed/foryou/`, sans champ éditable focalisé et sans menu `aria-haspopup` développé.
- Le daemon de test a été arrêté ; les onglets Chrome existants ont été conservés.
- Les 36 fichiers temporaires contenant les sorties live ont été supprimés. Le répertoire temporaire vide a été conservé parce que la politique de l'hôte a refusé sa suppression récursive.
