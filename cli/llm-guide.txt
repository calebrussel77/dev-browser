LLM USAGE GUIDE:
  Write small, focused scripts. Each script should do ONE thing: navigate, click, fill, or check.
  End each script by logging the state you need for the next decision.
  Use descriptive page names like "login", "checkout", or "results" instead of "page1".
  Named pages from browser.getPage("name") persist between script runs, so you usually do not need to re-navigate.
  When reusing an existing Chrome tab, call browser.listPages() first and pass its target ID
  to browser.getPage(targetId). An unknown name such as "main" creates a new named page.
  Inside page.evaluate(...), write plain JavaScript only - no TypeScript syntax in the browser context.
  On Windows/PowerShell, use here-strings to pipe multiline scripts:
    @"
    const page = await browser.getPage("main");
    console.log(await page.title());
    "@ | dev-browser --connect

  Choose the browser mode from the task:
    - Existing login, cookies, or user tabs matter: use `dev-browser --connect`.
    - Clean persistent automation: use `dev-browser --browser <task-name>`.
    - Disposable unattended automation: add `--headless` to a managed browser.
    - A CDP URL was explicitly supplied: use `dev-browser --connect <http-or-ws-url>`.
    `--headless` and `--ignore-https-errors` do not change an external browser
    attached through `--connect`.

  Prefer the interactive perception-action loop for consequential UI work:
    dev-browser --connect pages
    dev-browser --connect observe --page TARGET_ID --annotate --shot before.png
    dev-browser --connect find --page TARGET_ID --role button --name "Connect" --name-mode exact --within main --near "Profile" --scope document
    dev-browser --connect click --page TARGET_ID --ref R12 --from-state doc-7:184 --wait-text "visible,body,contains,Add a note" --shot modal.png
    dev-browser --connect confirm --page TARGET_ID --ref F0:R14 --expect "Naminsita Bakayoko" --shot confirm.png
    dev-browser --connect type --page TARGET_ID --ref R13 --text "Invitation note" --clear --shot typed.png
    dev-browser --connect click --page TARGET_ID --ref F0:R14 --from-state doc-7:190 --confirm-token TOKEN --shot sent.png
    dev-browser --connect click --page TARGET_ID --ref R12 --trace
    dev-browser trace show LAST

    `observe` returns compact protocol-v2 state plus stable refs with role, name,
    visibility, viewport coordinates, and main/aside/dialog landmark paths.
    `find` takes a fresh snapshot on every call. It keeps the natural query form
    and also accepts combinable role/name/within/near/frame/scope/state filters;
    use index only as an explicit last resort. Matches report exact reasons,
    confidence, score gap, ambiguity, duplicate-disambiguating context, and
    actionability state. `click` and `type` automatically return the refreshed
    snapshot, refs, and coordinates. Ref actions share bounded visibility,
    stability, enabled-state, scrolling, and obstruction checks. `click` reports URL/snapshot/dialog/aria-expanded
    changes. Typed `--wait-*` conditions are event-driven and cover text, URL,
    refs, dialogs, toasts, popups, downloads, file choosers, navigation,
    responses, failed requests, and network idle. A retry requires evidence that
    the prior attempt had no side effect; guarded and irreversible actions are
    never retried. Link refs fall back to an interactive button descendant
    or ancestor. Input uses trusted Playwright mouse/keyboard events and never
    HTMLElement.click(). The browser and page remain alive between commands.

    Every `--shot` result contains an absolute PNG path. Open that path with the
    available image-viewing tool before the next consequential action. Screenshot
    pixels, ref boxes, and `--xy X,Y` are all CSS pixels, regardless of DPR. Refs
    remain valid while the same DOM element survives; use fresh returned refs.
    Before irreversible actions, run `confirm --ref REF --expect RECIPIENT`, then
    consume its short-lived single-use token on the final ref action with
    `--from-state STATE --confirm-token TOKEN`. `--expect-text` remains v1 compatibility.
    Invalid, expired, reused, or out-of-scope tokens return
    `CONFIRMATION_INVALID` with process exit status 8.

    Machine discovery and diagnostics:
      dev-browser schema --json
      dev-browser capabilities --compact
      dev-browser examples click
      dev-browser doctor --connect --json
    The CLI automatically restarts an idle daemon when its embedded runtime,
    protocol, Playwright, or QuickJS provenance is stale. It refuses to kill
    in-flight work. Use `--trace` only when detailed diagnostics are needed;
    traces are redacted, size-bounded, retained under ~/.dev-browser/tmp/traces,
    and available with `dev-browser trace show LAST`. External CDP tracing is
    best-effort and reports a warning when full context tracing is unavailable.

  Quick inspection:
    dev-browser --connect <<'EOF'
    const tabs = await browser.listPages();
    console.log(JSON.stringify(tabs, null, 2));
    EOF

    dev-browser --connect <<'EOF'
    const tabs = await browser.listPages();
    const target = tabs.find(tab => tab.url.includes("app.example.com"));
    if (!target) throw new Error("No matching tab");
    const page = await browser.getPage(target.id);
    console.log(JSON.stringify({
      id: target.id,
      url: page.url(),
      title: await page.title(),
    }, null, 2));
    EOF

  AI snapshots for element discovery:
    dev-browser <<'EOF'
    const page = await browser.getPage("main");
    const result = await page.snapshotForAI();
    console.log(result.full);
    // Returns { full: string, incremental?: string }.
    // Optional args: { track?: string, depth?: number, timeout?: number }.
    // Read result.full to identify the right element.
    // Then interact with it using Playwright:
    // await page.getByRole("button", { name: "Continue" }).click();
    // Re-run page.snapshotForAI({ track: "main" }) after the page changes.
    EOF

  Choosing your approach:
    Unknown pages: use page.snapshotForAI() first to discover the page, then interact based on what you find.
    Known pages/selectors: skip the snapshot and use direct Playwright selectors like page.click(), page.fill(), or page.locator() for faster, more reliable automation.
    Existing browser tabs: match with both URL and title, because either value can be duplicated or stale.
    After navigation, submission, or another material state change, re-read the URL/title or snapshot instead of assuming success.

  Screenshots for visual state:
    dev-browser <<'EOF'
    const page = await browser.getPage("main");
    const buf = await page.screenshot();
    const path = await saveScreenshot(buf, "debug.png");
    console.log(path);
    EOF

  Waiting patterns:
    dev-browser <<'EOF'
    const page = await browser.getPage("search-results");
    await page.waitForSelector(".results");
    await page.waitForURL("**/success");
    console.log(JSON.stringify({
      url: page.url(),
      title: await page.title(),
    }, null, 2));
    EOF

  Dev server navigation:
    For local dev servers (Next.js, Vite, etc.), prefer:
      await page.goto(url, { waitUntil: "domcontentloaded" });
    The default "load" wait can hang on HMR, streaming, or other long-lived dev-server connections.
    Use "load" only when you specifically need every subresource to finish loading.

  Error recovery:
    If a script fails, the page usually stays where it stopped.
    Reconnect to the same page name, take a screenshot, and log the URL/title:
    dev-browser <<'EOF'
    const page = await browser.getPage("checkout");
    const path = await saveScreenshot(await page.screenshot(), "debug.png");
    console.log(JSON.stringify({
      screenshot: path,
      url: page.url(),
      title: await page.title(),
    }, null, 2));
    EOF

    Diagnose before restarting the workflow:
      dev-browser doctor --json
      dev-browser status
      dev-browser browsers
      dev-browser stop

    Runtime mismatches are normally repaired automatically when the daemon is idle.
    Use `dev-browser stop` only for explicit recovery or shutdown.

  Common Playwright Page methods:
    page.goto(url, { waitUntil: "domcontentloaded" })
                                           Navigate to a URL; prefer this on dev servers
    page.title()                           Get the current page title
    page.url()                             Get the current URL
    page.snapshotForAI(options)            Get an AI-optimized snapshot; returns { full, incremental? }
                                           Options: { track?: string, depth?: number, timeout?: number }
    page.getByRole(role, { name })         Target elements discovered from the snapshot
    page.textContent(selector)             Get the text content of an element
    page.innerHTML(selector)               Get the inner HTML of an element
    page.fill(selector, value)             Fill an input field
    page.click(selector)                   Click an element
    page.type(selector, text)              Type text character by character
    page.press(selector, key)              Press a key such as Enter or Tab
    page.waitForSelector(selector)         Wait for an element to appear
    page.waitForURL(url)                   Wait for navigation to a URL
    page.screenshot()                      Capture a screenshot buffer; save it with saveScreenshot(...)
    page.$$eval(selector, fn)              Run a function on all matching elements
    page.$eval(selector, fn)               Run a function on the first matching element
    page.evaluate(fn)                      Run JavaScript in the page context (plain JS only)
    page.locator(selector)                 Create a locator for chained actions

  Connecting to a running Chrome instance:
    Auto-discover Chrome with debugging enabled:
      dev-browser --connect <<'EOF'
        console.log(JSON.stringify(await browser.listPages(), null, 2));
      EOF

    Connect to a specific CDP endpoint:
      dev-browser --connect http://localhost:9222 <<'EOF'
        console.log(JSON.stringify(await browser.listPages(), null, 2));
      EOF

    To launch Chrome with debugging enabled:
      chrome.exe --remote-debugging-port=9222
      google-chrome --remote-debugging-port=9222

    Or visit chrome://inspect/#remote-debugging to configure.

    Reliability checklist for agents:
      1. Prefer `dev-browser --connect` with no URL. This lets dev-browser read
         Chrome's DevToolsActivePort file and probe common CDP ports.
      2. Call browser.listPages() before browser.getPage(targetId). Target listing
         does not attach every renderer; only the selected page is attached.
      3. If `http://localhost:9222/json/version` returns 404, do not assume CDP
         is unusable. Retry with `dev-browser --connect` or pass the exact
         ws://127.0.0.1:<port>/devtools/browser/... URL from DevToolsActivePort.
      4. If listPages() succeeds but getPage(id) fails, the browser connection is
         healthy and the selected renderer is the likely problem. Test one known-light
         tab before treating the entire browser or CDP endpoint as broken.
      5. A CDP-unresponsive selected renderer may be replaced by a fresh tab at the
         same URL in the same authenticated browser context. Continue with the Page
         returned by getPage(), but do not assume it is the original physical tab.
         Cookies and login state survive; unsaved DOM-only form/editor state does not.
         If exact tab identity or unsaved state matters, use desktop/browser control
         or ask the user to recover the original tab instead of retrying indefinitely.
      6. If Playwright logs `<ws connected>` and then times out, raw Chrome/CDP
         may be reachable while Playwright failed during attach. Use a short
         timeout such as `--timeout 10` and run `dev-browser stop` before retrying
         after upgrades or environment changes.
      7. `--timeout SECONDS` controls both the Playwright CDP attach timeout and
         the script execution timeout.

  Tips:
    - Use console.log(JSON.stringify(...)) for structured output.
    - Prefer page.snapshotForAI() for structure; use screenshots when visual layout or styling matters.
    - Keep page names stable across scripts so you can resume work after failures.
    - Close only pages the automation created or the user explicitly asked to close.
      Never close pre-existing user tabs merely to clean up.
    - Each --browser name maps to a separate daemon-managed browser instance.
    - Use --connect to attach to an existing browser; omit the URL to auto-discover Chrome with debugging enabled.
    - Use short timeouts (--timeout 10) so scripts fail fast instead of hanging on missing elements or stuck CDP attach.
    - Add --headless for unattended automation; omit it when you want to watch the browser window.
