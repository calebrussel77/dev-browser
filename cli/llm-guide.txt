LLM QUICK GUIDE:
  Start with `dev-browser capabilities --compact`. Read `dev-browser schema
  --json` only when a command fails for a grammar reason. Use
  `dev-browser examples COMMAND` for a focused recipe.

  Browser choice:
    - Existing login, cookies, or user tabs: `dev-browser --connect`.
    - Clean persistent profile: `dev-browser --browser TASK`.
    - Disposable run: add `--headless` to a managed browser.
  Run `pages` first and select an existing tab by URL/title and target id.
  An unknown page name creates a new persistent page.

  FAST PATH FOR REVERSIBLE UI:
    1. Use a semantic action directly; it performs a fresh find and acts only
       on one unambiguous target:
         dev-browser --connect click --page TARGET --role button --name "Open" --within main
    2. Read with `text --within`; use `observe --within` to choose a target,
       not to read long content.
    3. Combine predictable steps with `batch` (JSON from stdin or --file).
    4. Use sandboxed scripts for bulk extraction on known pages.
    5. Add `--shot` only when layout matters or before an irreversible action.

  Useful compounds:
    dev-browser type --page TARGET --role textbox --name "Search" --text "query" --press Enter
    dev-browser type --page TARGET --fill R1=Ada --fill R2=Lovelace
    dev-browser navigate --page TARGET https://example.com --observe main
    dev-browser click --page TARGET --role button --name "Open" --then-text main

  `batch` accepts 1..20 protocol-v2 actions plus standalone wait steps:
    {"page":"TARGET","steps":[
      {"kind":"click","role":"button","name":"Open","within":"main"},
      {"kind":"assert","within":"main","text":"Ready"}
    ],"stopOnError":true,"observeAfter":"delta"}

  SAFETY PATH FOR IRREVERSIBLE UI:
    Observe/find the exact target, use fresh refs and --from-state, inspect a
    screenshot when layout matters, then run `confirm --ref REF --expect TEXT`.
    Consume its short-lived token only on the final guarded action with
    `--from-state STATE --confirm-token TOKEN`. If no dialog exists, use
    `click --require-ancestor-text TEXT`. Never retry an irreversible action
    without proof that no side effect began.

  Output is compact JSON by default. `observe` omits element records; add
  `--elements` for compact boxes or `--verbose` only for diagnostics. `find`
  returns compact candidates. Refs are R# or F#:R# and states are versioned;
  after rerender, use the semantic recovery command returned by stale/target
  errors. Typed waits (`--wait-*`) replace sleeps.

  Sandboxed scripts are QuickJS, not Node.js: no require/import/process/fs or
  network APIs. Pages are Playwright Page objects. End scripts with bounded
  structured output, preferably `console.json(value)`. File helpers are
  restricted to ~/.dev-browser/tmp. Prefer `goto(..., {waitUntil:
  "domcontentloaded"})` for streaming/HMR pages.

  Diagnostics:
    dev-browser doctor --connect --json
    dev-browser examples click
    dev-browser trace show LAST
  Use `--trace` only when normal typed errors are insufficient. Close only
  pages created by the automation or explicitly authorized by the user.
